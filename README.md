# Low-level optimizations in high-level HDLs: Is there a benefit? Clash version

This repository contains the Clash and Verilog source code, synthesis
scripts, and evaluation data accompanying the paper

> O. Keszocze, T. Petersen, A. Friedemann, and M. B. Stuart,
> **"Low-level optimizations in high-level HDLs: Is there a benefit?"**,
> International Workshop on Boolean Problems (IWSBP), 2026.


## Summary

The paper investigates whether using low-level, hand-tuned optimizations
in a high-level, functional Hardware Description Language (HDL) pays off
in terms of synthesized circuit area — and whether it is worth the added
implementation effort.

As a working example, we implement an unsigned bit-serial
multiply-accumulate (MAC) unit in the functional HDL
[Clash](https://clash-lang.org/) in **16 different configurations**,
combining four independent design choices:

- **Modeling style** — Mealy machine vs. state monad
- **Product representation** — `BitVector n` vs. `Vec n Bit`
- **Counter type** — off-the-shelf `Index n` vs. one-hot encoding
- **Data access** — index-based vs. rotation-based

To separate architectural overhead from HDL-specific overhead, the same
architectural variants were additionally hand-written in **Verilog**.

All designs were synthesized for **27 bit-widths** using the open-source
[LibreLane](https://github.com/librelane/librelane) flow and the
**SkyWater 130 nm** PDK, comparing the resulting standard-cell area.

**Key findings:**
- Mealy-vs-monad and `BitVector`-vs-`Vec` have only a marginal effect on area.
- The counter type and, especially, the access pattern (indexing vs.
  rotating) have a substantial effect.
- Hand-written Verilog is smaller than the Clash-generated designs in
  practically all configurations.

## How to generate the data

### Clash

The obtain the Verilog files from the Clash implementation is a two stop process:

1.  Generate all Clash variants by running `stack run iwsbp26` in the main folder. This will create all required Clash source files in the `benchmarks_iwsbp26/generated_clash/clash` folder. The benchmarks are split into separate files in order to prevent out of memory issues when compiling all from a single file.
2. Run the `generate.sh` script from within the `benchmarks_iwsbp26/generated_clash/` folder. The Verilog files will be generated in the `verilog` folder.

### Verilog

To generate the Verilog files for the various bit-widths based on the handwritten template, run the `generate.sh` script  in the `benchmarks_iwsbp26/handwritten-verilog` folder. The Verilog files will be generate in the subfolder `iwsbp26_verilog`.

### Librelane

Run your preferred synthesis flow in order to obtain area data for the different designs.
